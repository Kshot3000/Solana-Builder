Solana in 30 seconds

Accounts & lamports

Everything on Solana is an account: wallets, tokens, programs and data all live in accounts holding lamports, the smallest unit of SOL (1 SOL = 1,000,000,000 lamports). Balances are whole lamports — a SOL amount never has more than 9 decimal places.

Programs

Smart contracts are called programs. They are stateless code; the state they work on lives in separate accounts they own. The SPL Token program, for example, manages every classic Solana token through token accounts it owns.

Fees & rent

A transaction pays a base fee of 5,000 lamports per signature, plus optional priority fees. Accounts pay rent for the data they store — or hold two years of rent up front (the rent-exempt minimum) and pay none again.

Speed

Proof of History gives the network a shared clock before consensus, so validators can order transactions fast: blocks land roughly every 400 milliseconds and finality follows in seconds. That speed is why Solana hosts busy DEXs, payment rails and consumer apps.

Tools — educational models

Each tool runs entirely in your browser and is labelled for what it is: a model that teaches the mechanic, never a live quote.

1. SOL ⇄ lamports converter

Exact conversion with integer math — no rounding, no floating point. Fill in one side and convert.

2. Constant-product swap model

The x·y=k mechanic behind AMM pools across Solana (Raydium CP-Swap, Orca and others): the fee comes off your input, the rest trades against the reserves, and the price moves against you as size grows.

3. Rent-exempt minimum calculator

What an account must hold to be rent-exempt: (128 + data length) × 3,480 lamports per byte-year × 2 years. Try 0 for a plain wallet account, 82 for a token mint, 165 for a token account.

4. Impermanent-loss calculator

For a 50/50 constant-product position: how far the LP position trails simply holding, when the price moves by the ratio you enter — the cost that pool fees have to beat.

5. Transaction fee estimator — base + priority fee

What a transaction costs before rent: a base fee of 5,000 lamports per signature, plus an optional priority fee — ceil(compute-unit limit × compute-unit price ÷ 1,000,000) lamports, where the price is in micro-lamports per compute unit. The priority fee is charged on the limit you request, not the compute you use, and a transaction's limit is capped at 1,400,000 compute units.

Getting started building on Solana

  1. Install the Solana CLI from the official installation guide, then point it at devnet: solana config set --url devnet.
  2. Make a devnet wallet and fund it free: solana-keygen new, then solana airdrop 2. Devnet SOL has no value — it exists so you can break things safely.
  3. Learn the account model first (Tool 3 above): every program you write allocates accounts, and rent-exempt minimums decide how much SOL each one locks up.
  4. Price a transaction before you send it (Tool 5 above): 5,000 lamports per signature plus a priority fee charged on the compute-unit limit you request — simulate, then set the limit close to real usage instead of overpaying for headroom you never use.
  5. Install Anchor from anchor-lang.com and run anchor init: you get a Rust program, an IDL and TypeScript tests in one scaffold.
  6. Read a real swap before writing one: run Tool 2 with a big amount in and watch price impact grow — that curve is what every AMM on Solana prices against.
  7. Test on devnet, then localnet: anchor test spins up a local validator; deploy to devnet only when tests pass. Never learn on mainnet with real funds.
  8. Ship and catalogue it: the full checklist lives in the getting-started guide in the repo.
